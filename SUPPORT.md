## Security issues

Do not publish vulnerability details, private transfer data, pairing invitations/capabilities, certificate private keys, signing material, provisioning secrets, or other secrets in a public GitHub issue.

Follow `SECURITY.md` and report security-sensitive findings privately to **sanskarin@outlook.in**.

Security-sensitive examples include authentication/authorization bypass, path traversal, unsafe overwrite, certificate/pinning bypass, replay weakness, private-key exposure, sandbox/App Group data exposure, or unintended transfer-content disclosure.

## Public issues

Use GitHub issues for non-sensitive reproducible bugs and feature requests.

Before posting:

1. search existing issues;
2. reproduce on the latest relevant source/release if practical;
3. remove secrets/private data;
4. follow `docs/diagnostics-and-bug-reports.md`;
5. identify whether the problem is discovery, pairing, transfer, external share/drop, settings, packaging, or build/CI related.

## Release/support boundary

Hosted source compilation is not a guarantee that an unsigned development build is a production-supported package. Signed/device/store readiness is governed by the release process/checklist for the exact candidate.

## Scope

Community support cannot guarantee a response time, compatibility with every device/network/provider, data recovery, or restoration of a transfer interrupted by external operating-system, storage, network, provider, firewall, or security policy. Keep independent backups of important files.
